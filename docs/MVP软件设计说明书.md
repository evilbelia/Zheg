# 折桂 MVP 软件设计说明书

版本 0.1 / 需求 REQ-20261009-01～05、REQ-20261010-01～02 / 2026-10-10。

## 产品流程

手动编辑 / 粘贴文本模型整理 → 检查草稿并保存本地档案 → 打开目标网页并点击扩展 → 识别当前页面 → 规则匹配与本地识别记忆 → 自动模型处理待确认项（可关闭） → 修改档案来源或选择经历 → 勾选待填字段 → 确认填写 → 用户自行检查并提交。

演示网页使用同一套档案、规则、模型和 DOM 填写逻辑，内置虚构档案和不可提交的表单。真实扩展初次运行使用空档案。

预览展示网页标签、档案来源、待填值与结果。明确规则匹配且档案有值的字段默认选中；模型建议与记忆映射默认未选中。无法确定、缺少经历和空值不自动填写。已有内容默认保留，需逐字段勾选覆盖。

首版不支持跨页、iframe、自动新增经历、文件上传、验证码、自动提交或第三方自定义控件。只识别可见可编辑的原生 text/email/tel/date/month、textarea、单选组和单选 select，最多 200 个字段。已填写状态表示原生控件接受值，不保证第三方前端或服务端已接受申请。

## 实现架构

- JavaScript / Vite，双入口：index.html 演示；workspace.html 扩展侧边栏。
- Chrome / Edge MV3，最低 Chromium 116。background.js 配置点击工具栏图标打开侧边栏。
- 权限：activeTab、scripting、storage、sidePanel。无常驻全站读取权限；保存模型设置或测试连接时申请目标服务域名权限，识别时检查已获权限。
- src/adapter.js 区分演示 DOM 与 chrome.scripting / tabs 消息。
- src/dom.js 为自包含脚本，在隔离环境提取 DOM、维护扫描期间字段注册表并执行填写。扫描不修改输入值。
- src/profile.js 提供版本兼容、动态 schema、字段 / 板块 / 记录增删、数据校验、读取和控件兼容检查。
- src/profile-extraction.js 负责纯文本模型提取、输出校验与新值优先的草稿合并。
- src/matching.js 通过别名与分组上下文匹配，序号分配重复经历，转换日期和原生选项。
- src/model.js 负责过滤结构、构建提示、请求服务并校验输出，以及最小连接测试。
- src/model-config.js 提供 DeepSeek 默认配置、旧配置迁移与模型服务权限地址。
- src/recognition-memory.js 负责本地识别记忆的校验、复用与确认后的积累。
- src/storage.js 区分网站 / 扩展存储，独立保存凭据并迁移旧会话密钥。
- src/app.js / style.css 为侧边栏和演示界面。

没有业务后端、数据库、Docker 或 Python / Java 服务。无需环境变量。开发 npm run dev，构建 npm run build，输出 dist 为可加载扩展。

## 档案结构及存储

schemaVersion: 2；personal 为一条对象，education、internships 为最多 20 条记录的数组。保留原标准字段键和来源路径，每条标准记录新增 extraFields（自定义字段数组）与 removedFields（已删除标准键列表）。删除标准字段把值清空并记录 tombstone，界面 / 动态 schema / 读取值均排除；模型载入不恢复该标准字段。

sections 为最多 20 个同级自定义板块：`[{id:"s_<uuid>",title,records:[{fields:[{id:"f_<uuid>",label,value,type}]}]}]`；标准记录的 extraFields 采用同样字段结构。每板块最多 20 条记录、每记录最多 50 个自定义字段，标题最多 80 字且非空，同一记录标题不重复；全档案最多 500 个可见字段、序列化 UTF-8 最多 1 MB。所有值为最多 5000 字字符串；type 只允许 text/date/email/tel，date 使用 YYYY-MM。ID 由本地生成，限制为 s_ / f_ 前缀的安全字符，拒绝重复 ID、危险路径、未知类型。跨记录复用同一标题 / 类型的字段 ID；同 ID 的定义必须一致。标题在新增时输入，添加后只显示固定文字，不提供改名输入框；只编辑内容，换名需删除后重新添加。

版本 1 只接受原白名单字段，兼容读取并转为版本 2 内存结构，不立即写存储。版本 2 同样剔除未知属性；无效档案不覆盖存储。编辑草稿与已保存档案分离，手动输入 / 增删 / 模型载入后点击“保存档案”才替换本地存储，网页填写只使用已保存数据。切换选项卡保留草稿；刷新丢弃未保存编辑及粘贴原文。移除 JSON 导入 / 导出和演示档案载入入口。扩展初始为空，演示网页初次仍使用虚构测试档案。

扩展使用 chrome.storage.local；演示使用 localStorage，二者互不共享。无账号、云同步和加密，档案保存在当前浏览器配置中。

模型服务商、地址、名称与 autoInfer 开关本地保存；点击“保存模型设置”同时持久保存独立的 `modelCredential:{version:1,baseURL,key}`。扩展使用 chrome.storage.local；演示使用 zheg:modelCredential 的 localStorage。刷新、关闭重开与浏览器重启后恢复密码输入框及请求凭据。密钥不进入档案、modelConfig、识别记忆、模型正文或日志，只用于所选服务的 Authorization 请求头。不加密、不云同步；不同浏览器配置、网站源及扩展各自隔离。卸载、清除数据或临时隐私配置结束后无法恢复。

在任何凭据读取 / 写入前，扩展设置 local.setAccessLevel 为 TRUSTED_CONTEXTS，阻止注入脚本访问 local（包括档案和识别记忆）；可信扩展页面和后台仍可读写。不新增权限。凭据绑定完整 baseURL，地址不一致不返回密钥；更换服务商或编辑地址清空表单旧密钥，不将旧凭据自动带给新服务。模型名称切换仍使用同一服务凭据，仅保留当前服务一份密钥。

扩展保存时通过一次 local.set 写入配置和凭据，移除旧 session.modelKey；演示凭据写入失败时恢复之前的配置，界面不切换已保存配置 / 密钥。读取 / 迁移失败时密钥置空并明确提示，仍可使用本地规则与手动填写；读写错误提示固定且不展示底层错误或原始密钥。点击“清除已保存 API Key”移除旧会话密钥并写入空凭据标记，成功后清空当前输入框和内存密钥；不改变档案、配置或识别记忆。失败不假报成功；自定义无鉴权服务仍允许空密钥保存。

## 文本载入与档案编辑

档案页顶部 textarea 接受任意格式的纯文本（简历、叙述、列表、表格、JSON），最多 20000 字；不支持附件、图片或 OCR。只有用户点击“载入个人信息”才请求已保存模型配置，与自动网页识别开关独立。明确告知用户：粘贴原文与当前板块 / 小标题 outline 将发送给模型服务商；不发送现有档案值、网页、识别记忆或全部存储。原文只在当前页面内存，不写日志或本地存储。

使用 Chat Completions、20 秒超时、相同安全地址校验 / 已授予权限检查，未配置 / 无权限提示去智能识别保存设置。模型系统提示将 text 作为不可信材料，只提取原文明示事实、不执行指令、猜测或补造；不从身份证 / 学号推断日期，缺失日期不输出字段。输入 `{text,outline:[{title,fields:[label]}]}`；输出 `{sections:[{title,records:[{fields:[{label,value,type}]}]}]}`，不接受模型生成路径或 ID。每批 1～20 板块、每板块 1～20 记录、每记录 1～50 非空字段，最多 500 字段；拒绝重复板块 / 字段、非字符串、未知类型、空内容和超限数据；任一结构非法输出整体拒绝，忽略未知属性。输出受 prompt 约束但不保证无误或完整，用户必须核对。

REQ-20261010-01：提取边界在本地确定性规范化日期，不增加模型重试或自动调用。支持四位正年份加 1～2 位月份（YYYY-M / YYYY.M / YYYY/M）、同分隔符年月日、中文年月 / 年月日（日或号结尾），去除首尾空白；检查月份与实际日历（含闰年），单个合法日期转 YYYY-MM，日精度舍弃，UI 明示按月保存。模型将标准日期误标为 text 时在标准字段合并前做相同转换。仅年份、至今、区间、含多余文字、不确定格式或非法日历不提取片段、不猜月份：date 转为 text 并保留原文，不阻断其他信息。标准 / 已有自定义 date 字段无法转换的内容另存“标题（原文）”文本，避免污染 month 控件或撞上标准标题；原文标题最多 80 字。已删除的标准日期仍不恢复。现有持久档案校验继续只接受 YYYY-MM；规范化仅作用于新提取内容。结构 / 容量 / 权限错误仍拒绝整批并保持草稿和存储，降级仅是日期文本保存，绝不伪造模型回答。

REQ-20261010-02 合并在拷贝草稿上完成：模型在原有一次提取请求内先判断语义及板块，必须优先复用 outline 中同义标题；不同含义（主 / 备用邮箱、本人 / 家庭电话）分开，不生成本地路径或 ID，也看不到旧值。程序优先现有同名板块及标准板块别名，其他标题创建自定义板块。基本信息只接受本人一条记录。同一记录的同名 / 标准别名字段以本次非空新值更新，缺失旧字段保持；相同值不计更新。合并后计数 added / updated / skippedDeleted，已删除标准字段跳过不恢复。自定义字段保留标题、类型和 ID；date 类型仍遵守月份约束，不确定日期按前述原文机制保留。标准同义字段归一化后值 / 类型冲突则整批拒绝，相同则去重，避免响应顺序决定结果。

经历匹配：教育学校 / 实习公司必须与本地值完全一致；双方有开始日期且不同则区分，教育双方学历不同也区分。其他字段的值变化不阻止唯一身份匹配，可更新职位、描述和结束日期。自定义记录优先匹配姓名 / 项目名称 / 证书名称 / 标题；没有明确身份时可用关系 / 称谓 / 成员匹配，输入含姓名却没有对应项或有冲突时不能仅凭关系合并；无身份时仅完整一致记录去重。多个匹配或无匹配时使用空记录，否则追加，不按序号猜测。不同身份 / 周期仍独立。匹配不涉及模糊人名 / 公司名推断，模型归类或用户资料可能存在歧义，核对界面处理。

按批次稳定索引完成合并后，将本次涉及的非基本信息记录按模型输出顺序排在所属板块前面，同一索引去重，其余记录保持原相对顺序，包括演示经历。只重排草稿，保存后清除扫描状态，重新扫描默认映射新记录；网页已有值保护不变。未提到的演示记录不自动删除，用户可删除后保存。完整输出与最终档案均验证通过后才替换编辑草稿，不直接保存；HTTP / 网络 / 超时 / 非法结果 / 同义冲突 / 合并容量超限均保持原草稿和已保存档案。模型返回字符串仅以转义文本渲染，不执行 HTML 或脚本。

标准板块别名包括“实习工作经历”；“工作单位 / 担任职务 / 主要工作职责 / 主修专业”分别归入公司 / 职位 / 工作内容 / 专业，也用于后续规则匹配。载入前说明新值更新 / 未提供保留 / 本次经历优先；完成后显示新增与更新数量、已删除跳过数量、日期按月保存及核对后保存。旧值优先行为已由 REQ-20261010-02 替代，不改变网页填写时的已有内容保护。

每条记录有可展开“添加信息”：输入小标题、内容并确认添加；添加后以固定标题加内容框显示，不再显示“小标题”输入框与“内容”重复标签，标准板块扩展字段、自定义板块及模型载入字段一致；每个标准 / 自定义字段右上角 × 删除小标题及其内容，保存后生效。底部新增板块可创建家庭信息等大板块；新板块可增删记录及整板块。标准板块不删除，基本信息固定一条记录，教育 / 实习可清空记录及字段。删字段 / 板块后相应识别记忆失效；保存后重新扫描。

## 字段与映射协议

扫描消息 ZHEG_SCAN，响应：fields[] / unsupported / truncated。

字段：id（扫描期间 UUID）、label、type、section、groupId、options[{label,value}]、hasValue（布尔）。不会提取输入值、HTML、页面个人档案；原生选项和字段标签仍可能包含页面信息。

规则根据教育、实习、个人等分组消除歧义。重复分组按页面顺序默认对应档案序号，用户可在分组下拉中改记录，也可逐字段修改来源。来源路径只允许当前 profileSchema；索引由本地 UI 管理。标准字段沿用 personal.fullName / education[].school 等；标准记录的扩展字段为 internships[].extra.f_<id> / personal.extra.f_<id>，新板块为 sections.s_<id>[].f_<id>。不按任意路径访问对象，先由当前动态 schema 查找板块，再从白名单字段描述中取值。规则使用新增小标题作为别名，自定义板块按标题上下文隔离；重复网页板块按出现顺序对应记录，仍可手动切换。已删除字段不出现在来源选项或模型白名单中。

ZHEG_FILL 输入 items[{id,value,overwrite}]，响应 [{id,status,message}]。status 为 success / failed / skipped。只使用扫描注册表中的 DOM 引用；校验字段仍存在、可见、类型/标签/分组/选项未变。已有内容且没有 overwrite 时跳过；值需通过原生格式、范围、长度约束。填写触发 input/change，单选触发 click，不触发 submit。重新扫描使旧 ID 失效；切换标签页和刷新页面需重新识别。

档案精度为月。month 控件直接填写；date 控件使用当月 1 日，预览明确提示用户检查。

## 自动智能识别与模型配置

默认配置 `{provider:"deepseek",baseURL:"https://api.deepseek.com/v1",model:"deepseek-chat",autoInfer:true}`。服务商下拉支持 DeepSeek、自定义兼容接口；DeepSeek 地址只读，模型下拉为 deepseek-chat / deepseek-reasoner；自定义模式可编辑地址和模型名（最多 200 字）。API Key 为密码输入框。旧配置中其他服务地址迁移为 custom，显式关闭状态保留，缺失开关默认开启；不修改档案版本。

只有用户点击识别 / 重新识别时执行：本地规则 → 已确认记忆（存在时优先于规则）→ 若开启且有未映射字段，自动模型分析一次 → 填写预览。保存配置、打开网页、修改档案均不调用识别模型。设置页开关立即持久化，下次扫描生效。DeepSeek 缺少密钥时提示配置；自定义无鉴权服务允许空密钥。规则 / 记忆覆盖全部字段时不发请求；无需把整个识别库发送给模型。每次重新识别是新扫描，不缓存未确认模型建议或 null 结果。

POST {baseURL}/chat/completions，Bearer 鉴权，20 秒超时。远程必须 HTTPS，本机 localhost / 127.0.0.1 可 HTTP；拒绝地址中的用户名、密码、查询参数和 fragment。演示需要服务允许浏览器 CORS。扩展在保存设置或测试连接的用户手势内申请所选域名权限，自动分析仅使用 permissions.contains 检查，不在扫描后的异步阶段申请。权限拒绝时可保存设置和本机密钥，自动识别保留本地结果、提示重新保存以授权。未配置、权限拒绝、HTTP、网络、超时及非法输出均不阻断规则和手动路径。

网页识别请求只有待确认字段结构与当前动态档案 schema（路径、经过过滤的小标题 / 板块描述及类型，不含值）。字段标签限长、过滤长数字 / 邮箱 / URL，已知分组归一化，未知分组发送“未知分组”，选项仅发送最多 30 条过滤后的显示文字，不发送选项 value、已有输入、个人档案、网页地址或 HTML。过滤无法识别所有个人信息：模型设置中提供当前待发送 JSON，界面说明自动调用的数据边界并可关闭。该过滤和系统提示不能保证彻底防御提示注入；模型仅返回映射，不能直接执行工具或网页操作。

输出 {mappings:[{fieldId,profilePath}]}，不确定返回 null，忽略自报置信度。程序校验 ID 存在、无重复、路径在 schema、类型兼容。任一非法映射拒绝整个响应，不部分应用。系统提示将页面文字视作不可信数据。模型建议默认不选中，须用户核对勾选后填写。

### API Key 连接测试

“测试 API Key”验证当前表单草稿，不自动保存配置或密钥。使用同一安全地址校验、权限和超时机制，发送单条固定消息 `Reply with OK.`，max_tokens 为 64（deepseek-reasoner 为 1024，为推理后的最终回答留空间）。不发送任何网页结构、档案或识别库。HTTP 成功且 choices[0].message.content 为非空、长度不超过 50000 的字符串才表示成功，不能保证后续额度或服务可用；测试可能产生费用。不强制回答恰为 OK，以兼容模型输出差异。

401 表示凭据无效 / 失效，403 表示访问权限不足，429 提示限流 / 额度不足；其他 HTTP 提示检查地址、模型或服务状态。网络 / 超时 / 无效 JSON / 空回答均提示失败，不展示服务响应正文、回答或原始网络错误，避免回显凭据。

## 本地识别记忆

独立存储 recognitionMemory：`{version:1,entries:[{origin,section,label,type,options,path}]}`。origin 仅网站源（不含页面路径、查询参数），section 为已知板块种类或经过过滤检查的命名板块，label 为标准化标签，options 为标准化选项标签。按 origin / section / label / type / options 联合匹配，不跨网站、板块、控件类型或选项串用。保留 matchFields 分配的经历索引，不存储个人值、网页已有值、HTML、扫描 ID、经历序号或 API Key。

模型建议不会直接保存；选中并确认填写且返回 success 的模型 / 手动映射才入库。失败、跳过、未选中、仅规则匹配不积累；显式手动纠正可替换同一键的旧规则，同批次出现冲突映射时删除该键，避免顺序决定识别结果。记忆映射默认未勾选，需要检查后选择，防止错误积累后自动填写。加载时校验版本、字段类型与当前动态档案路径；扩展字段另保存 definition（当前标题 / 类型签名）以让改名后旧记忆失效，不含值。删除字段的旧路径被拒绝；冲突记录忽略。未分组 / 未知分组、被过滤或截断的标签 / 板块 / 选项不入库；过滤仍无法识别所有个人信息，库仅保存在本机。

最多保留最近 500 条，确认同键时刷新顺序。库不提供日常编辑界面，设置页可清空；与个人档案分开存储，清空不影响档案与模型配置。演示使用 localStorage，扩展使用 chrome.storage.local，二者隔离。旧版本回滚会忽略新增存储；REQ-20261009-03 将档案升级为版本 2，兼容与回滚见下节。

## 升级与回滚

REQ-20261009-05：扩展持久凭据不存在时读取旧 session.modelKey，非空字符串才迁移到绑定当前配置地址的 local 凭据；成功写入后移除会话副本。持久凭据存在时不迁移，包括空密钥标记；非法版本 / 类型 / JSON 提示读取失败，不回退旧密钥。迁移失败不继续模型调用并可重新保存。已结束的旧会话密钥和演示内存密钥无法找回，需最后输入并保存一次。反复读取不会重复迁移；清除后的空标记防止旧会话副本重新恢复。无数据库或档案迁移。回滚旧代码前用清除按钮移除持久密钥；旧版忽略新凭据存储并恢复会话 / 内存策略。扩展更新保留 ID 和浏览器配置，开发模式使用同一 dist 路径重新加载，卸载再安装会丢失存储。

validateProfile 可重复地把版本 1 转为版本 2 内存结构，保存前不改变原存储。首次保存版本 2 时，若读取的是版本 1 且 profileV1Backup 不存在，先备份原始版本 1；之后保存不会覆盖快照。备份失败则不写新版档案。保存新版后清理 recognitionMemory 中不存在的路径；清理失败只提示，运行时仍校验路径，不使用旧映射。

profileV1Backup 含旧个人信息，保存在原来的本机存储中；删除字段操作只修改当前档案，不会抹去该升级快照。回滚会恢复快照里的旧值（包括可能后来删除的信息），不含升级后新增信息。旧代码不支持版本 2，不能直接切换代码宣称无损回滚。回滚前保留当前版本 2 快照；恢复版本 1 后加载旧代码。扩展开发者工具内可执行以下可重复恢复操作，无旧快照时保留当前标准字段投影；不是默认升级步骤，不在应用中自动执行：

```js
const saved = await chrome.storage.local.get(['profile', 'profileV1Backup', 'profileV2Backup']);
if (saved.profile?.schemaVersion === 2) {
  if (!saved.profileV2Backup) await chrome.storage.local.set({ profileV2Backup: saved.profile });
  const { personal, education, internships } = saved.profile;
  await chrome.storage.local.set({ profile: saved.profileV1Backup ?? { schemaVersion: 1, personal, education, internships } });
}
```

演示存储采用对应的 zheg:profile / zheg:profileV1Backup / zheg:profileV2Backup 键，在浏览器开发者工具中保留 / 恢复，不清空浏览器数据。重新升级可以从 profileV2Backup 恢复完整新版数据并重新检查，不能自动把版本 1 的后续编辑合并回新版快照。
